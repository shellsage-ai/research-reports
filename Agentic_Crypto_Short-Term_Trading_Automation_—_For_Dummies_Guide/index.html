Agentic Crypto Swing-Trading Lab For Beginners

🎯 What Is It?

This is a setup for a crypto trading bot that tests and runs short-to-medium trades automatically, while AI tools help you research, review results, and improve the strategy. The safest version starts with fake money, called dry-run mode, so you can learn without risking real funds.

The best practical approach is: let rules place trades, let AI analyze and improve, and keep humans in charge of turning on real money.

🤔 Why Does It Matter?

Crypto markets move 24/7, so watching charts manually is exhausting. A bot can follow a written plan all day and night without panic-buying, revenge-trading, or forgetting your rules.

Personally, this gives you a repeatable system: backtest first, paper trade next, then only consider tiny real-money trades after the bot proves it behaves.

⚠️ Safety Note

Do start in dry_run: true. Do not give any AI agent withdrawal permissions. Do not use leverage or futures as a beginner.

Do use a separate exchange API key named freqtrade-dryrun-or-small-live. Do set max_open_trades: 3, stake_amount: 25, and tradable_balance_ratio: 0.3 while learning.

Do not let OpenClaw, Codex, or a local model directly edit API-key files or place trades. Use them to read logs, summarize backtests, and propose code changes for you to approve.

Phase 2: Add A Simple Swing Strategy

  1. Create the strategy file ~3 minutes
@'
from freqtrade.strategy import IStrategy
from pandas import DataFrame
import talib.abstract as ta
import freqtrade.vendor.qtpylib.indicators as qtpylib


class WeeklySwingStrategy(IStrategy):
    INTERFACE_VERSION = 3

    timeframe = "4h"
    startup_candle_count = 100
    can_short = False

    minimal_roi = {
        "0": 0.08,
        "720": 0.04,
        "2160": 0.02,
        "4320": 0
    }

    stoploss = -0.08
    trailing_stop = True
    trailing_stop_positive = 0.025
    trailing_stop_positive_offset = 0.05
    trailing_only_offset_is_reached = True
    process_only_new_candles = True

    def populate_indicators(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        dataframe["ema20"] = ta.EMA(dataframe, timeperiod=20)
        dataframe["ema50"] = ta.EMA(dataframe, timeperiod=50)
        dataframe["rsi"] = ta.RSI(dataframe, timeperiod=14)
        return dataframe

    def populate_entry_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        dataframe.loc[
            (
                (dataframe["ema20"] > dataframe["ema50"]) &
                (qtpylib.crossed_above(dataframe["rsi"], 40)) &
                (dataframe["volume"] > 0)
            ),
            "enter_long"
        ] = 1
        return dataframe

    def populate_exit_trend(self, dataframe: DataFrame, metadata: dict) -> DataFrame:
        dataframe.loc[
            (
                (
                    qtpylib.crossed_below(dataframe["rsi"], 70) |
                    (dataframe["ema20"] < dataframe["ema50"])
                ) &
                (dataframe["volume"] > 0)
            ),
            "exit_long"
        ] = 1
        return dataframe
'@ | Set-Content .\user_data\strategies\WeeklySwingStrategy.py
  1. Download historical data ~5-20 minutes
docker compose run --rm freqtrade download-data --exchange kraken --pairs BTC/USD ETH/USD SOL/USD XRP/USD ADA/USD --days 730 -t 4h

💡 Tip: 730 days gives about two years of data, enough to catch different market moods.

  1. Backtest the strategy ~2-10 minutes

⚠️ Don’t: Start live trading because one backtest looks good. One lucky period proves very little.

🌍 Real-World Analogy

Think of Freqtrade like a slow cooker. You put in the recipe once, and it follows the recipe exactly instead of improvising.

Think of dry-run mode like a flight simulator. You can crash fake planes while learning, instead of risking real passengers.

Think of backtesting like watching old game footage before a match. It does not guarantee tomorrow’s win, but it shows whether your plan has obvious weaknesses.

Think of Qwen/Ollama like a local mechanic in your garage. It can inspect your machine privately, but it should not be handed your bank card.

Think of API keys like valet keys for your exchange account. Give the bot permission to park the car, never permission to empty the garage.

❌ Common Mistakes & How to Avoid Them

  1. Turning on live trading too soon
    What goes wrong: Real money disappears during normal bot bugs.
    Why it happens: A good-looking backtest feels exciting.
    Fix: Require 30 days of dry-run before live mode.

  2. Giving withdrawal permission to an API key
    What goes wrong: A stolen key can drain funds.
    Why it happens: Beginners enable every checkbox.
    Fix: Enable only query balance, query orders, create/modify orders, and cancel orders.

  3. Using too many pairs
    What goes wrong: The bot opens messy trades everywhere.
    Why it happens: More coins feel like more opportunity.
    Fix: Start with BTC/USD, ETH/USD, SOL/USD, XRP/USD, ADA/USD.

  4. Trusting AI-generated strategies blindly
    What goes wrong: The code may look smart but lose money.
    Why it happens: AI writes confidently.
    Fix: Backtest, dry-run, and inspect every change.

  5. Ignoring fees and slippage
    What goes wrong: Small wins vanish after costs.
    Why it happens: Charts show clean prices, real orders do not.
    Fix: Prefer 4h or 1d trades over frantic 1m scalping.

  6. Trying to force the NPU to run everything
    What goes wrong: Setup time gets wasted.
    Why it happens: “AI chip” sounds like it should run all AI.
    Fix: Use CPU/iGPU/RAM for large language models; use NPU for supported ONNX workloads.

✅ Key Takeaways

  • Start with dry-run, not real money.
  • Let rules trade; let AI review.
  • Never enable withdrawal permissions.
  • Use spot trading before anything else.
  • Backtest across at least one year.
  • Smaller stakes reveal mistakes cheaply.
  • Logs are your trading black box.

🔬 Going Deeper

Your Ryzen AI Max+ 395 has 16 CPU cores, 32 threads, up to 128 GB memory support, Radeon 8060S graphics, up to 126 total AI TOPS, and up to 50 NPU TOPS. That is excellent for a local research machine, but the trading bot itself barely needs that much power.

Qwen3-30B-A3B has about 30.5 billion total parameters but activates about 3.3 billion at a time. That “A3B” part is why it can be more efficient than a normal 30B model.

Ollama’s qwen3:30b package is about 19 GB in its common quantized form. Your 128 GB RAM machine has plenty of headroom for the model, Docker, logs, and historical data.

The sample strategy uses 4-hour candles. That means each candle summarizes 4 hours of price action, which is calmer than 1-minute trading and better aligned with trades lasting days or weeks.

The stoploss is -0.08, meaning the bot exits around an 8% loss before a bad trade becomes catastrophic. The first profit target is 0.08, meaning 8% profit, then the required profit gets smaller as time passes.

📖 Glossary

Agentic: Able to take actions toward a goal, not just answer questions.

API key: A digital key that lets software access an account.

Backtest: A test of a strategy using old market data.

Dry-run: Fake-money trading mode.

Exchange: A marketplace where crypto is bought and sold.

Freqtrade: An open-source crypto trading bot.

Leverage: Borrowed trading power that can multiply wins and losses.

NPU: Neural Processing Unit, a chip for certain AI workloads.

Ollama: Software for running AI models locally.

Pair: A traded market like BTC/USD.

Slippage: The difference between expected price and actual fill price.

Stoploss: A rule that exits a trade after a set loss.
